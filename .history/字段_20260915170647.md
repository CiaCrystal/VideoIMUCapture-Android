# 手持_后台测试2.txt 字段说明

> 本说明根据 VideoIMUCapture-Android 项目的字段文档、TXT 格式化代码、Protobuf 定义以及实际采集文件整理。

## 1. 文件概况

| 区块 | 数量 | 含义 |
|---|---:|---|
| `RECORDING` | 1 | 录制开始时间 |
| `IMU_INFO` | 1 | IMU 设备信息 |
| `EXPERIMENT_INFO` | 1 | 实验标签 |
| `CAMERA_INFO` | 1 | 相机静态能力 |
| `CAPTURE_CONFIG` | 1 | 本次 Camera2 请求 |
| `IMU_DATA` | 1758 | 同步后的 IMU 样本 |
| `FRAME_METADATA` | 518 | Camera2 帧元数据 |
| `FRAME_TIMESTAMP` | 519 | 编码器视频帧时间 |
| `TOUCH_EVENT` | 4 | 触摸事件 |

本次采集：

- IMU 持续约 `17.541 s`，平均约 `100.17 Hz`。
- 相机元数据持续约 `17.231 s`，平均约 `30.00 Hz`。
- 编码器时间戳持续约 `17.264 s`，平均约 `30.00 Hz`。
- 没有出现 `RECORDING_ERROR`。
- 没有输出 `OIS_SAMPLE` 或 `LENS_INTRINSICS_SAMPLE`。

文件开头以 `#` 开始的内容只是格式注释，不是操作指令。

## 2. 通用格式规则

- 文件使用 `[SECTION]` 和 `key=value` 结构。
- 同一个 section 可以重复出现，不能按普通 INI 文件解析。
- `start_unix_time_ms` 是 Unix 墙上时间。
- `time_ns`、`sensor_timestamp_ns` 和 `time_us` 使用单调采集时钟，不是 Unix 时间。
- `time_us` 转换为纳秒时需要乘以 `1000`。
- 三轴 IMU 向量顺序为 `[x, y, z]`。
- 四元数顺序为 `[x, y, z, w]`。
- `[]` 表示数据不可用或没有导出，不能解释成全零向量。
- 空字符串表示未填写或没有提供。
- Camera2 状态中的 `-1` 通常表示没有报告。
- 字符串可能包含转义后的 `\\`、`\r` 和 `\n`。
- 解析 `key=value` 时应只在第一个 `=` 处分割。

### Accuracy 枚举

| 值 | 名称 | 含义 |
|---:|---|---|
| 0 | `UNRELIABLE` | 不可靠，或尚未收到准确度回调 |
| 1 | `LOW` | 低 |
| 2 | `MEDIUM` | 中 |
| 3 | `HIGH` | 高 |

Accuracy 是 Android 给出的等级，不是误差、方差或置信区间。

## 3. RECORDING

### `start_unix_time_ms`

写入器创建 TXT 时的 Unix 毫秒时间。

本文件：

```text
start_unix_time_ms=1789461533211
```

对应北京时间：

```text
2026-09-15 16:38:53.211 +08:00
```

它不一定等于首个 IMU 样本或首个视频帧的时间。

## 4. IMU_INFO

### `source`

固定为：

```text
gyroscope,accelerometer,magnetometer
```

这是应用添加的数据类别标签，不是硬件名称。

### 传感器描述字段

- `gyroscope_info`：陀螺仪的 Android `Sensor.toString()` 描述。
- `accelerometer_info`：加速度计描述。
- `magnetometer_info`：磁力计描述。

描述字符串中的常见子字段：

| 子字段 | 含义 |
|---|---|
| `name` | 驱动报告的传感器名称 |
| `vendor` | 驱动报告的厂商名称 |
| `version` | 传感器实现版本 |
| `type` | Android 传感器类型编号 |
| `maxRange` | 最大测量范围 |
| `resolution` | 测量分辨率 |
| `power` | 驱动报告的功耗 |
| `minDelay` | 最小事件间隔，单位 μs |

本文件中的传感器类型：

| 传感器 | type | Android 类型 |
|---|---:|---|
| 陀螺仪 | 16 | `TYPE_GYROSCOPE_UNCALIBRATED` |
| 加速度计 | 35 | `TYPE_ACCELEROMETER_UNCALIBRATED` |
| 磁力计 | 14 | `TYPE_MAGNETIC_FIELD_UNCALIBRATED` |

`minDelay` 是硬件能力信息，不等于此次录制的实际采样间隔。

### 分辨率字段

- `gyroscope_resolution_rad_s`：陀螺仪分辨率，单位 rad/s。
- `accelerometer_resolution_m_s2`：加速度计分辨率，单位 m/s²。
- `magnetometer_resolution_uT`：磁力计分辨率，单位 μT。

### `estimated_accelerometer_frequency_hz`

录制开始时，根据加速度计事件时间间隔估算的频率。

本文件为：

```text
estimated_accelerometer_frequency_hz=0
```

这表示写入 `IMU_INFO` 时尚未形成有效估计，不表示没有采样。根据实际 `IMU_DATA` 计算，本次平均频率约为 `100.17 Hz`。

### `accelerometer_placement_m`

加速度计相对设备参考点的位置：

```text
[x, y, z]
```

单位为米。本文件为 `[]`，表示设备没有提供或录制开始时尚未取得。

## 5. IMU_DATA

IMU 同步器以陀螺仪时间戳为基准，将加速度和磁场插值到陀螺仪时刻。

### `time_ns`

原始陀螺仪事件的 `SensorEvent.timestamp`，单位 ns。

它是单调时钟，不是 Unix 时间。

### 陀螺仪字段

- `gyroscope_rad_s`：三轴角速度，单位 rad/s。
- `gyroscope_drift_rad_s`：驱动估计的三轴零偏，单位 rad/s。
- `gyroscope_accuracy`：最近一次陀螺仪准确度等级。

`gyroscope_rad_s` 不是欧拉角、旋转角或姿态四元数。

如需使用驱动偏置进行补偿，可按分量计算：

```text
gyroscope_corrected = gyroscope_rad_s - gyroscope_drift_rad_s
```

### 加速度计字段

- `accelerometer_m_s2`：三轴加速度，单位 m/s²，包含重力响应。
- `accelerometer_bias_m_s2`：驱动估计的三轴零偏，单位 m/s²。
- `accelerometer_accuracy`：最近一次加速度计准确度等级。

### 磁力计字段

- `magnetometer_uT`：三轴磁场，单位 μT。
- `magnetometer_bias_uT`：驱动估计的三轴磁场偏置，单位 μT。
- `magnetometer_accuracy`：最近一次磁力计准确度等级。

磁力计偏置不是磁偏角。

### 坐标系

项目没有把 IMU 向量旋转到视频图像坐标系。

设备处于自然方向且面向屏幕时：

- x 轴向右。
- y 轴向上。
- z 轴从屏幕向外。

本文件全部 1758 条记录的陀螺仪、加速度计和磁力计 accuracy 都为 `3/HIGH`。

## 6. EXPERIMENT_INFO

### 字段

- `source`：固定为 `experiment`。
- `experiment_id`：实验编号。
- `trial_group`：试验分组。
- `device_pose`：设备姿态标签。
- `support_condition`：手持、支撑等条件。
- `af_experiment_mode`：实验层面的 AF 模式标签。
- `ois_experiment_mode`：实验层面的 OIS 模式标签。
- `camera_covered`：镜头是否被遮挡。
- `scene_type`：场景类型。
- `target_type`：目标类型。
- `notes`：实验备注。

本文件中：

```text
af_experiment_mode=CONTINUOUS_PICTURE
ois_experiment_mode=OFF
```

其余多数实验字段为空，因为当前应用没有对应的完整填写界面。

`camera_covered=` 是未知或未填写，不能解释成 `false`。

## 7. CAMERA_INFO

## 7.1 相机及设备信息

- `source`：固定为 `camera`。
- `camera_id`：Camera2 相机 ID。本文件为 `0`。
- `device_manufacturer`：设备厂商，本文件为 `vivo`。
- `device_model`：设备型号，本文件为 `V2183A`。
- `android_version`：Android 版本，本文件为 `13`。
- `android_api_level`：API Level，本文件为 `33`。
- `camera_hardware_level`：Camera2 硬件能力原始枚举。
- `camera_hardware_level_name`：硬件能力名称。

本文件：

```text
camera_hardware_level=1
camera_hardware_level_name=FULL
```

## 7.2 OIS 能力

### `available_ois_modes`

相机声明支持的 OIS 控制模式：

| 值 | 含义 |
|---:|---|
| 0 | OFF |
| 1 | ON |

本文件：

```text
available_ois_modes=[1]
```

表示厂商只声明了 ON 模式。该能力数组不能替代逐帧实际状态。

### `available_ois_data_modes`

相机声明支持的 OIS 位移数据报告模式。

### `available_ois_data_modes_key_available`

用于区分：

- OIS 数据能力键不存在。
- 能力键存在，但返回空数组。

本文件：

```text
available_ois_data_modes=[]
available_ois_data_modes_key_available=false
```

表示能力键不可用。

### `supports_ois_data`

是否支持控制 OIS 数据报告模式。本文件为 `false`。

### `supports_ois_samples`

CaptureResult 可用键中是否存在 OIS 样本字段。本文件为 `true`。

这不保证实际一定会返回样本。本次所有帧的 `ois_sample_count` 都是 0。

## 7.3 AF 能力

### `available_af_modes`

支持的 AF 模式：

| 值 | 名称 |
|---:|---|
| 0 | OFF |
| 1 | AUTO |
| 2 | MACRO |
| 3 | CONTINUOUS_VIDEO |
| 4 | CONTINUOUS_PICTURE |
| 5 | EDOF |

本文件支持：

```text
[0, 1, 2, 3, 4]
```

### 对焦距离

- `minimum_focus_distance_diopters`：最近对焦距离，单位 m⁻¹。
- `hyperfocal_distance_diopters`：超焦距，单位 m⁻¹。
- `focus_distance_calibration`：对焦距离标定级别。
- `focus_distance_calibration_name`：标定级别名称。

本文件：

```text
minimum_focus_distance_diopters=10
hyperfocal_distance_diopters=0.2
focus_distance_calibration=0
focus_distance_calibration_name=UNCALIBRATED
```

当标定可靠时，距离可近似按下式换算：

```text
distance_m ≈ 1 / diopters
```

但本设备为 `UNCALIBRATED`，不能将换算结果作为高精度测距。

### 支持能力字段

- `supports_af_state`：是否能读取逐帧 AF 状态。
- `supports_lens_state`：是否能读取镜头移动状态。
- `supports_focus_range`：是否能读取焦距范围。
- `supports_af_scene_change`：是否能读取 AF 场景变化。
- `supports_lens_intrinsic_calibration`：是否能读取普通逐帧内参。
- `supports_lens_intrinsics_samples`：是否支持 API 35+ 高频内参样本。

## 7.4 相机内参

### `intrinsic_params_fx_fy_cx_cy_s`

项目按照输出尺寸和方向变换后的相机内参：

```text
[fx, fy, cx, cy, skew]
```

其中：

- `fx`、`fy`：像素焦距。
- `cx`、`cy`：主点坐标。
- `skew`：像素轴倾斜参数。

可以组成内参矩阵：

```text
K = [[fx, skew, cx],
     [0,  fy,   cy],
     [0,  0,    1]]
```

本文件：

```text
[859.71094, 859.71094, 479, 640, 0]
```

### `original_intrinsic_params_fx_fy_cx_cy_s`

CameraCharacteristics 返回的原始内参，没有经过项目的输出方向和尺寸变换。

本文件：

```text
[2751.075, 2751.075, 2048, 1536, 0]
```

### `distortion_params_k1_k2_k3_k4_k5`

镜头畸变参数：

```text
[k1, k2, k3, k4, k5]
```

- 前三项为径向畸变参数。
- 后两项为切向畸变参数。

本文件为 `[]`，表示没有导出有效参数，不能解释为镜头畸变为零。

## 7.5 防抖配置

- `optical_image_stabilization`：应用配置的 OIS 开关。
- `video_stabilization`：应用配置的数字视频防抖开关。
- `distortion_correction`：应用配置的畸变校正开关。

这些字段描述应用配置，不是逐帧实际结果。

本文件三项均为 `false`。

## 7.6 方向、时间源和镜头位姿

- `sensor_orientation_degrees`：相机传感器方向，本文件为 `90°`。
- `focus_calibration`、`focus_calibration_name`：静态对焦距离标定枚举，本文件为 `0/UNCALIBRATED`。
- `timestamp_source`、`timestamp_source_name`：Camera2 时间源，本文件为 `1/REALTIME`。
- `lens_pose_reference`、`lens_pose_reference_name`：镜头位姿参考，本文件为 `0/PRIMARY_CAMERA`。
- `lens_pose_rotation_x_y_z_w`：镜头位姿四元数。
- `lens_pose_translation_m`：镜头位姿平移，单位 m。

`REALTIME` 表示相机时间理论上可以与 elapsed-realtime 类时钟比较，不表示 Unix 时间。

镜头位姿是设备提供的静态信息，不是 SLAM 轨迹。

- `pre_correction_active_array_width_px`：有效阵列宽度。

## 8. CAPTURE_CONFIG

该区块描述应用发送给 Camera2 的请求，不是相机最终执行结果。

- `source`：固定为 `camera_request`。
- `config_id`：配置记录编号。
- `requested_af_mode`：请求的 AF 模式原始值。
- `requested_af_mode_name`：请求的 AF 模式名称。
- `requested_af_trigger`：AF 触发值。
- `requested_af_trigger_name`：AF 触发名称。
- `requested_focus_distance_diopters`：手动对焦请求值。
- `requested_optical_stabilization_mode`：请求的 OIS 模式。
- `requested_ois_data_mode`：请求的 OIS 数据报告模式。
- `requested_video_stabilization_mode`：请求的 DVS 模式。
- `requested_ae_mode`：请求的自动曝光模式。
- `requested_awb_mode`：请求的自动白平衡模式。
- `requested_fps_range`：目标 FPS 范围。
- `capture_template`：Camera2 请求模板原始值。
- `capture_template_name`：请求模板名称。

本文件的主要配置：

```text
requested_af_mode=4
requested_af_mode_name=CONTINUOUS_PICTURE
requested_af_trigger=0
requested_af_trigger_name=IDLE
requested_focus_distance_diopters=
requested_optical_stabilization_mode=0
requested_ois_data_mode=-1
requested_video_stabilization_mode=0
requested_ae_mode=1
requested_awb_mode=1
requested_fps_range=[30, 30]
capture_template=3
capture_template_name=TEMPLATE_RECORD
```

解释：

- 使用连续图片 AF。
- 没有主动触发一次性 AF。
- 没有设置手动焦距。
- 请求关闭 OIS。
- OIS 数据模式不可用或未请求。
- 请求关闭数字防抖。
- AE 为 ON。
- AWB 为 AUTO。
- 目标帧率固定为 30 FPS。
- 使用录像请求模板。

## 10. FRAME_TIMESTAMP

该区块保存没有匹配到 Camera2 元数据的编码器帧。

- `source`：固定为 `video_encoder`。
- `matched_to_camera_metadata`：该区块固定为 `false`。
- `time_us`：编码器帧的 presentation timestamp，单位 μs。
- `video_frame_number`：编码器帧编号。

项目匹配条件为：

```text
abs(1000 * time_us - sensor_timestamp_ns) <= 10000 ns
```

也就是时间差不超过 `10 μs`。

本文件中：

- 518 条 `FRAME_METADATA` 全部未匹配。
- 519 条 `FRAME_TIMESTAMP` 全部未匹配。
- 两边持续时间和帧率基本一致。
- 两种时间戳的原点约相差 35.24 小时。

因此项目的直接时间比较无法建立帧对应关系。

这不表示视频没有帧，而是表示 TXT 中没有形成可信的 Camera2 帧与编码帧映射。仅按照记录顺序强行对应只能作为启发式方法，不能视为项目提供的准确匹配。

## 11. TOUCH_EVENT

- `source`：固定为 `touchscreen`。
- `time_ns`：转换到 elapsed-realtime 时间基准后的触摸时间。
- `action`：Android 触摸动作原始值。
- `action_name`：动作名称。
- `x_px`、`y_px`：App 窗口中的触摸坐标，单位 px。
- `pressure`：触摸压力值。
- `size`：触摸接触面积描述。
- `pointer_id`：触点 ID。
- `target_label`：实验目标标签。
- `trial_id`：试验编号。

动作枚举：

| action | action_name |
|---:|---|
| 0 | DOWN |
| 1 | UP |
| 3 | CANCEL |
| 5 | POINTER_DOWN |
| 6 | POINTER_UP |

本文件记录：

- 2 次 `DOWN`。
- 1 次 `CANCEL`。
- 1 次 `UP`。

`x_px` 和 `y_px` 是 App 窗口坐标，不是视频图像坐标。

当前没有 target/trial 标注界面，因此：

```text
target_label=
trial_id=-1
```

## 12. 本文件未出现的区块

### OIS_SAMPLE

当相机提供 OIS 位移样本时，每个样本包含：

- `parent_camera_frame_number`
- `sample_index`
- `time_ns`
- `x_shift_px`
- `y_shift_px`

OIS 位移单位为像素，不是陀螺仪角速度或镜片机械位移。

本文件所有 `ois_sample_count=0`，因此没有该区块。

### LENS_INTRINSICS_SAMPLE

API 35+ 且设备支持时，每个样本包含：

- `parent_camera_frame_number`
- `sample_index`
- `time_ns`
- `fx`
- `fy`
- `cx`
- `cy`
- `skew`

本设备为 API 33，且 `supports_lens_intrinsics_samples=false`，因此没有该区块。

### RECORDING_ERROR

写入队列过载时会包含：

```text
[RECORDING_ERROR]
message=...
```

本文件没有该区块，说明没有记录到显式的写入队列过载错误。

但缺少该区块不能绝对证明录制完整，例如进程被强制终止时可能来不及写入错误信息。

## 13. 下游解析建议

1. 先根据 section 类型分流，再解析对应字段。
2. 不要把整个文件作为普通 INI 文件读取。
3. 所有时间戳使用 64 位整数。
4. 比较 `time_us` 和 `time_ns` 前，先把 `time_us` 乘以 1000。
5. 不要将 `start_unix_time_ms` 直接与传感器单调时间戳相减。
6. `[]`、空字符串、`0` 和 `-1` 必须根据具体字段分别解释。
7. IMU 数据应按 `time_ns` 排序。
8. 相机元数据应使用 `camera_frame_number` 和 `sensor_timestamp_ns`。
9. 本文件中不能直接依赖 `matched_to_video` 建立视频帧映射。
10. 相机静态内参不能代替相机—IMU 联合标定。
11. `gyroscope_drift_rad_s` 是驱动偏置估计，不是完整 IMU 标定结果。
12. 后台录制的视频使用 MP4 旋转元数据；提取图片时应应用旋转，才能与 TXT 中的 960×1280 尺寸和变换后内参对应。
